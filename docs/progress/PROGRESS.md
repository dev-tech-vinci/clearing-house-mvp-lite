- Bug found and fixed during this phase's own Playwright verification (see `docs/progress/DECISIONS.md`): `providers.organizationName`/`firstName`/`lastName` combined `.min(1)` with `.optional()`, but the dialog's `defaultValues` initializes the hidden half of the individual/organization split to `''` rather than `undefined`, which fails `.min(1)` silently — `form.handleSubmit` never called `onSubmit`, so there was no error, no toast, and no network call at all. Fixed by dropping `.min(1)` from those three fields (the real non-emptiness requirement is already enforced by the cross-field refine + DB check constraint).
- Also fixed as prerequisite/consistency work: two other Zod/TypeScript inference bugs surfaced while typing the 6 create/edit dialogs against schemas with `.default()` fields (ternary `Create/UpdateSchema` resolvers don't infer cleanly against `useForm`'s generic) — resolved by giving each entity a single permissive `*FormSchema` (id field optional) for client-side typing, keeping the stricter `Create`/`Update` schemas as the real server-side validation boundary via `enhanceAction`.
- Commands run: `pnpm lint` (11/11 tasks pass, 2 pre-existing warnings unrelated to this phase), `pnpm typecheck` (12/12 tasks pass), `pnpm --filter web supabase:reset`, `supabase db test` (40/40 pgTAP assertions pass across both suites — 22 new + 18 from Phase 2), `npx playwright test tests/entities` (3/3 pass), `npx playwright test tests/navigation tests/organizations tests/authentication tests/account` (31/33 pass — 2 pre-existing failures unrelated to this phase, root cause now identified as OTP-expiry under parallel test load, see Known Issues).
