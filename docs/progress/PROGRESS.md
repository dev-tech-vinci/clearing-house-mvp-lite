- Bugs found and fixed during this phase's own verification (see `docs/progress/DECISIONS.md` for full detail): (1) `TicketsList` originally took a `detailHref: (ticketId) => string` function prop passed from an async Server Component — React Server Components cannot serialize a function across the server/client boundary, and this crashed the entire `/home/support` page with a full error-boundary page on every load; fixed by changing the prop to a plain `basePath: string`. (2) The document "View"/"Download" buttons called `window.open(result.signedUrl, ...)` *after* `await`-ing the server action — by the time the promise resolved, the click was no longer inside the browser's "current user gesture" window, so the popup was silently blocked (it opened, but never navigated); fixed by opening a blank popup synchronously inside the click handler and setting `popup.location.href` once the signed URL resolves (which also required dropping `noopener` from the `window.open` call, since that flag makes the return value `null`). (3) The access-session start form was shown even before a support user had self-assigned the ticket, so clicking "Start" would always throw a confusing RLS error; fixed by adding an `isAssignedToMe` prop that shows an explanatory message instead of the form until the ticket is actually assigned to the caller — a real UX fix, not just a test workaround.
