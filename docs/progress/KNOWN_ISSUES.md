# Known Issues / Blockers

> Anything that stops a phase's acceptance criteria from being met, recorded instead of worked around silently.

## Open

- **2 pre-existing Playwright specs still fail against `next dev`, now with a different symptom than before Phase 2:** `tests/account/account.spec.ts:36` ("user can update their password") times out on `page.fill('[data-test="account-password-form-password-input"]')` (the password field never becomes available); `tests/authentication/password-reset.spec.ts:11` ("will reset the password and sign in with new one") times out on `page.waitForURL('/update-password')` (never navigates there after the reset-password email link is followed). Both are distinct from each other and from the dev-tools-overlay click-interception symptom resolved in Phase 2 (below) — confirmed by isolating `account.spec.ts:36` alone and reading its captured error, not just inferred. Not caused by any Phase 2 change (organizations/access-control code doesn't touch the auth/password-reset path). Not investigated further this phase since it's outside Phase 2's scope; needs its own root-cause pass, ideally alongside Phase 9's full test-pyramid work.
- **Every package's `lint` script creates a stray `'node_modules'` directory (literal single-quote in the folder name)**, confirmed root cause found in Phase 2: each `package.json`'s `lint` script passes `--cache-location "'node_modules/.cache/.eslintcache'"` (extra single-quotes meant to be stripped by a POSIX shell), and in this environment (Git Bash via pnpm/turbo on Windows) those quote characters are passed through literally instead of being stripped, so ESLint creates a directory whose name literally starts with `'`. Reproduced live while staging the Phase 2 commit: running `pnpm lint` on the two new Phase 2 packages created `packages/features/{access-control,organizations}/'node_modules/.cache/.eslintcache'`, which were staged by accident and then unstaged before committing. Untracked (not matched by `.gitignore`, since the pattern is `node_modules` not `'node_modules'`), visible in `git status`, and now present under `apps/web`, every `packages/features/*` and most of `packages/*`, and `tooling/{eslint,prettier}`. Not fixed this phase (would mean editing every package's lint script + `.gitignore`, out of scope) — flagged for cleanup, and safe to delete (`git clean` won't touch them since they're not ignored, so they'd need manual removal, e.g. `rm -rf "**/'node_modules'"`).

## Resolved during Phase 2

- **The floating "Open Next.js Dev Tools" button (Next.js 15 dev-mode indicator) was intercepting Playwright clicks**, documented as an open issue after Phase 1 closeout (3 failing specs: `account.spec.ts:36`, `auth.spec.ts:35`, `password-reset.spec.ts:11`). Resolved by adding `devIndicators: false` to `apps/web/next.config.mjs`. This was found while chasing a *different* bug (a Radix Dialog/DropdownMenu interaction stuck-overlay issue — see `docs/progress/DECISIONS.md`) and turned out to be an unrelated, genuine fix in its own right: `auth.spec.ts:35` ("will sign-in with the correct credentials") now passes. The other 2 specs still fail, but with a different symptom — see "Open" above.
