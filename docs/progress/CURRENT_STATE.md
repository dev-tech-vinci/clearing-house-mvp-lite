New package `packages/features/remittances`. New routes: Adjudicate button + remittance detail panel on `/home/claims/[id]`; `/home/remittances` list with Match EFT; `/home/dashboard` now shows separate rejection-rate (from `processing_jobs`) and denial-rate (from `remittances`) cards, queried from two independent tables so the two can never merge in code. REST: `GET /api/v1/remittances`, `POST /api/v1/remittances/{id}/match-eft`. The rejection-vs-denial hard rule now spans two phases by construction: Phase 6 never writes an adjudication-stage event; Phase 7 never writes a denial to `processing_jobs`. Platform/support roles still have no cross-org RLS bypass into tenant-owned data.
